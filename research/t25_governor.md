## 2. The methodology, and a mistake caught before publishing

Both replays run over every **non-X** signal (`status != "skipped_d"`, 2,256 of 45,193) —
not the 1,017 the legacy grader chose to TRADE (an S/A/C-graded signal is a governor
candidate whether or not the legacy B/A/A+ acceptance rule happened to trade it, matching
x7's own methodology of filtering the raw signal population directly), but also **not** the
full 45,193.

**Why the X-graded 42,937 have to be excluded, and it is not a style choice.** The first
version of this script did NOT exclude them and produced n=7,044, mean **+9.59R** — an
absurd number, caught before it went in this file. Cause: `skipped_d`/`X` rows carry
placeholder entry/stop pairs left over from a signal `_grade_pa` vetoed on candle shape
before any real stop was placed (stop distances as small as $0.01, `stop_pct` 0.006–0.007%).
Three examples pulled from the offending rows: **+109R**, **+212.5R**, **+67169R**, against a
real-fill population capped at −1.25R / +21.4R (the four other statuses' actual min/max).
Excluding them is not a new convention invented for this report — it is exactly what
`signal_runner.py::_sac_ladder_grade` already does live: `SAC_LADDER_REGRADE_ALL` defaults
`False`, so "a signal the incumbent chain already graded X is LEFT alone" and never reaches
`_tier()`. The replay matches the shipped code; the first draft did not, and is not the
number reported here.

**This is not the same population as `a3_s_cap_sweep.md`'s cap sweep (n=129 there).** a3
