# T9 -- omen-5.0 vs omen-5.1, head-to-head over the same two years

The identical `research/t8_two_year.py` replay (2024-08-12 to 2026-08-11, 500 trading days, 29 symbols across the three pools, $1,000 risk, `STOP_ON_CLOSE=1`, `LADDER_MODE=B`) run under the two default sets, then joined trade-by-trade on `(symbol, date, entry_i)`. Population is the **traded** book -- fired, engine grade A+/A/B -- 1017 trades, the same line `t8_two_year.md` reports. Win rate counts decided trades only (scratches out of the denominator); EV is mean R per trade and counts every trade, scratches included.

## The two arms

- **arm 5.0** -- the committed 5.0 defaults: three-clause S bar (displacement AND mesh both hard-block S to tier C), S+ tier live (top 3 S signals/day universe-wide), `PESSIMISTIC_FILL=0`.
- **arm 5.1** -- the new defaults from T1/T2: mesh-veto-only S (the displacement clause demotes a no-displacement B&R to A instead of dropping it to C; the mesh S-veto is the only hard block), no S+ tier (the rank is deleted, every S+ folds back to S), `PESSIMISTIC_FILL=1`.

Both arms share the same engine grade path, so neither change can move which trades FIRE -- the fill rule only rewrites the exit price of an open trade and the S tier is a reported label. The join below is the proof, not the assertion.

**Where the S+ trades landed in 5.1:** all 56 of the 5.0 S+ trades reappear in 5.1 as plain **S** (5.1's S count = 85, = 5.0's S+ 56 + S 29). The other regrade is the **displacement demotion**: 245 traded break-and-retest signals were tier **C** in 5.0 (the displacement clause hard-dropped them) and tier **A** in 5.1 (T1 demotes a no-displacement B&R to A instead of dropping it). These still FIRE in both arms -- `_calibration_grade` floors the first with-trend B&R of the day to engine grade B regardless, so a no-displacement B&R can be a *traded* B -- which is why the demotion reaches the traded tier table (5.0 A 11 -> 5.1 A 256; 5.0 C 921 -> 5.1 C 676). It moves the label, never the P&L: `austin_tier` is reported only, nothing branches on it.

## 3. The churn report

The two traded books joined on `(symbol, date, entry_i)`. Four counts, with a worked example row for each that has any rows. Full join: `research/t51_churn.jsonl` (301 differing trades).

- **added** -- trades 5.1 takes that 5.0 did not: **0**
- **dropped** -- trades 5.0 took that 5.1 does not: **0**
- **regraded** -- same trade, different tier: **301** (56 S+->S from the deleted S+ rank, 245 C->A from the displacement demotion)
- **reoutcomed** -- same trade, same tier, different win/loss (T2's fill fix): **0**

**added**
  - *0 -- none. Both arms fire an identical entry set: the fill rule only rewrites an open trade's exit price and the S tier is a reported label, so 5.1 takes no trade 5.0 lacked.*
**dropped**
  - *0 -- none, for the same reason as added.*
**regraded**
  - example: AAPL 2025-01-29 bar 15 (BR call @ 236.0999): tier C -> A (outcome unchanged: loss, -1.00R both arms)
**reoutcomed**
  - *0 -- none. T2 already measured why: the stop is tested before every profit rung in both exit paths, so a bar that tagged a target and closed beyond the stop was already booking the loss before the pessimistic flag existed. The fill fix moves 0 traded outcomes.*

The level-retire clause (`LEVEL_RETIRE_TOUCHES=2`) skipped **0** signals across all 29 symbols over the window -- it is inert here, so the 'retired third-touch demoted to A' half of T1 moves nothing in either arm. (checked, not assumed.)

## 4. The largest driver of the P&L delta

There is no P&L delta to drive. The two arms book the same 1017 trades at the same outcomes: P&L $887,892 both arms (Δ $+0), EV +0.873R both arms (Δ +0.000R), win rate 55.0% both arms (Δ +0.0). The only thing 5.1 changed was **labels**: the S+ rank was deleted (56 trades S+ -> S) and the displacement clause was loosened (245 traded B&R C -> A). Both are pure tier relabels -- `austin_tier` is reported only, nothing branches on it -- so together they account for the entire `regraded` count of 301 and move zero P&L. Nothing was added, nothing dropped, nothing re-outcomed. omen-5.1 was a classification change, not a selection change -- and the churn join is what turns 'every backtest looks the same' from a suspicion into a measured fact.
