# G7.1 / track `faraway` -- never refuse for distance, find another target

> *"we dont need to refuse trades that have a far level away for Q8, we just need to find other targets."* -- Austin, 2026-08-29 (`Projects/omen-rulebook.md`)

Generated by `research/g71_faraway.py` from `research/bt2y_trades.json` (500 sessions 2024-08-21 -> 2026-08-21, 2437 traded). 2437 rows replayed, 0 without archived bars. Entry/stop/side/entry-bar fixed; only the target varies.

## 0. The answer

**Nothing in the shipped engine refuses a trade because the target level is far.** The only two level-distance vetoes it ever had -- `LEVEL_BLOCK_CAP` (`signal_runner.py:181`) and `MESH_S_VETO` (`signal_runner.py:1222`) -- were about a level sitting *in the way*, not *far away*, and R25 turned both OFF on 2026-08-29. The tag they emit, `[capped C: level $X blocks 2R path]`, appears **0 times in all 76,019 signals** of the two-year book (`research/g71_faraway_tags.py`). Q8's "don't refuse" is already satisfied.

**What the engine does instead is degrade the target, and it does it on 2135 of 2437 traded rows (87.6%).** `backtest_week.py:851-858` appends `math.floor(scale_level)+1.0` to the runner-target candidate list *unconditionally* and takes `min()`, so the runner can never aim more than $1 past the session extreme however far the real level is. On 964 of those rows a real PDH/PDL/PMH/PML was out there and the whole dollar overrode it.

**And Austin's fix, read literally, is not the win.** Aiming at the far level itself (`uncapped`) moves +0.0171R against its own +/-0.0333R bar -- a NULL -- and costs 3 green weeks (87/105 vs 90/105). What *is* outside its bar is pushing the shipped target OUT to the trade's own **measured move** when the measured move is further -- `or_mmove`, section 4c: whole-book mean R **+0.5715 vs +0.5487**, a paired **+0.0228R against a +/-0.0183R bar**, months green 25/25 (shipped 25/25) and weeks green 90/105 (shipped 90/105). It is the first exit-side arm in this project to move outside its own bar in the POSITIVE direction -- T5 found 29 arms outside their bar and every one moved DOWN (`research/t5_structural-target.md`). It is worth +55.6R over two years, and it does **not** reach the 2.0R money gate; nothing on the exit side can.

## 7. Recommendation, and the diff

**Recommended fallback chain: keep the shipped runner target, and push it OUT to the trade's own measured move when the measured move is further. Never nearer, never a refusal.**

```
runner_tgt = furthest_of(
    min(named six-levels beyond the scale point, floor(scale)+$1),   # shipped
    measured move: entry + (leg high - leg-origin swing low)          # NEW
)
```

Why this and not the others, every reason a measured one:

1. `uncapped` -- Austin's sentence read literally, aim at the far level itself -- is a NULL (+0.0171R vs a +/-0.0333R bar) and it costs 3 green weeks. Aiming at a level 5.26R away turns runners into holds.
2. `or_atr3` is the biggest mover but it breaks durability -- 24/25 months green against the shipped 25/25. Durability is a gate, not a tiebreak.
3. `or_2r` is safe and real but half the size.
4. Every entry-anchored chain in section 5 LOSES to the shipped exit. The runner must stay anchored at the scale point; that is not a detail, it is -0.0993R when you get it wrong.
5. `or_mmove` is the only arm that is outside its bar, positive, and holds both durability gates (25/25 months, 90/105 weeks).

plus the flag and the helper, both new, at the top of `backtest_week.py`:

```diff
+# G7.1/faraway. OFF by default so no published number moves on this commit;
+# ON it books +0.0228R paired against a +/-0.0183R bar over the
+# 2-year book, 25/25 months and 90/105 weeks green.
+RUNNER_MEASURED_MOVE = os.getenv(
+    "RUNNER_MEASURED_MOVE", "0").strip().lower() in ("1", "true", "yes", "on")
+MMOVE_LOOKBACK = 30
+
+
+def measured_move(candles, i, entry, is_long, lookback=MMOVE_LOOKBACK):
+    """The breakout leg's own height projected from entry, or None.
+
+    Causal: the leg origin is the most recent swing CONFIRMED at or before
+    bar i-1 (a swing at j needs bar j+1, and j+1 <= i). Mirrors
+    research/g71_faraway.py::measured_move, whose --selftest proves the
+    value is unchanged when the tape after bar i is deleted."""
+    lo = max(1, i - lookback)
+    origin = None
+    for j in range(i - 1, lo - 1, -1):
+        a, b, c = candles[j - 1], candles[j], candles[j + 1]
+        if is_long and b.low < a.low and b.low < c.low:
+            origin = b.low
+            break
+        if not is_long and b.high > a.high and b.high > c.high:
+            origin = b.high
+            break
+    if origin is None:
+        return None
+    if is_long:
+        leg = max(c.high for c in candles[lo:i + 1]) - origin
+        return entry + leg if leg > 0 else None
+    leg = origin - min(c.low for c in candles[lo:i + 1])
+    return entry - leg if leg > 0 else None
```
